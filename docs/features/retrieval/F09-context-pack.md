> 在 Top-K 记忆进入答题 prompt 之前，把记忆块压到 `budget_ratio`（默认 0.8）× 官方渲染 token 以内，不调用任何模型。
> 按条数自动选策略：≤ 10 条角色缩写 + 紧凑，≤ 20 条电报式，其余直接删条；三者共用 Mixed-Score 排序。

---

## 背景

LoCoMo 答题 prompt 中记忆块占绝大部分输入 token。目标是记忆块 token 降约 20%（≥ 18%），
准确率相对官方渲染（九问基线）持平或上升都算达标，下降在 0.5 个百分点以内也算达标，且不增加模型调用。

数据：`mem2.0` 普通版（`schema_enabled=false`，`llm` 抽取）全量 LoCoMo 一轮召回落盘（每题 Top-200），
回放只换记忆块；作答 / 判分模型 GLM-5.2，24 并发，每臂 2 轮，配对差与 95% CI 按题计算。
会话 0–2 用于校准选策略；下表数据范围为会话 2–9（1,307 题）。

| Top-K | 策略 | 九问 | 打包 | 差 | 95% CI | 记忆 token/题 | 降幅 |
|---|---|---|---|---|---|---|---|
| 10 | 角色缩写 + 紧凑 | 84.62 | 85.08 | +0.46 | [−0.28, +1.19] | 384 → 297 | 22.6% |
| 20 | 电报式 | 88.18 | 88.14 | −0.04 | [−0.77, +0.69] | 752 → 593 | 21.1% |
| 50 | 直接删条 | 91.58 | 91.47 | −0.11 | [−0.91, +0.68] | 1,861 → 1,482 | 20.4% |

三档 CI 都跨 0：结论是「token 降 20–23% 时准确率持平」，不是提升。

## 决策

### 决策 1：Mixed-Score 排序，决定谁保留原文

```
mixed(i) = 0.45 × minmax(检索得分) + 0.50 × |问题词 ∩ 记忆词| / |问题词| − 0.05 × 记忆长度 / 总长度
```

词按 `[a-z0-9]+|[\u4e00-\u9fff]` 切分并小写。检索得分全为 0 时用名次代理（第一名 1.0、末名 0.0）。
同分按输入顺序。新近度与实体项权重为 0：首轮筛选（会话 0–4，Top-50 删条）中带新近度 0.50 的权重为 −1.97pp，
去掉新近度为 −1.31pp。

### 决策 2：三种策略，按条数自动选择

预算 = `budget_ratio` × 同批记忆官方渲染（`(日期) 正文` 每行一条）的 token 数。

| 策略 | 做法 | 适用 |
|---|---|---|
| `role_compact` | "the user / the assistant / user / assistant"（含所有格）缩写为 U / A，"a/an assistant" 等普通名词不动；同日记忆归入 `[日期]` 标题，去掉与标题同日的 `On YYYY-MM-DD, ` 前缀；引言末尾说明 "U = the user, A = the assistant."。仍超预算时按电报式规则处理尾部 | ≤ 10 条 |
| `telegraph` | Mixed-Score 序前 h 条原样；其余去同日日期前缀与虚词，保留否定词（not / no / never / without）、大写开头词与含数字的词；尾部条目内容词 ≥ 80% 已被前面覆盖则丢弃；h 取装得下的最大值，h = 0 仍超时从尾部删 | 11–20 条 |
| `drop` | Mixed-Score 序贪心装入，装不下的整条丢弃，保留条目原文、官方渲染 | > 20 条 |

分界来自校准与检验：Top-10 校准上角色缩写 + 紧凑 +0.39、电报式 +0.13；Top-20 校准上角色缩写 + 紧凑未达标
（−0.78）而电报式 +0.65；Top-50 检验上电报式未达标（−0.61）而删条达标（−0.30）。`strategy` 参数可显式指定任一策略。

### 决策 3：纯函数，不是检索算子

与 `cross_space.py` 同类：不访问存储、不调模型，无 Producer 注册、不进工厂、不改 `Retriever` 结果。
调用方（评测、Agent 的 prompt 组装）在拿到检索结果后自行调用。不放进 Discloser：本模块会重排与删条，
违反「Discloser 只做内容塑形」（`retrieval/AGENTS.md` 铁律 10）。

### 决策 4：token 计数器由调用方注入

`count_tokens` 默认是与 `pipeline_retriever` 同口径的字符估算（约 4 字符 1 token），不为核心包引入 tiktoken。
预算与实际用量用同一个计数器。评测侧注入 cl100k（`evaluation/shared/tokens.py`）；
cl100k 与 GLM-5.2 网关计得的降幅相差 < 0.3pp（40 题实测）。

### 决策 5：评测默认关，另给回放脚本

`run.py` 的 `CONTEXT_PACK` 默认 0，开启后每个 cutoff 切片打包后再作答，召回不变，打包统计写入
`test_response_v5*.json` 的 `context_pack` 字段与 `run_meta.json`。`context_pack_replay.py` 复用已落盘召回，
基线与打包两组各自计时作答、再判分，输出配对差与 CI，避免为对比重跑写入与召回（抽取的随机性会淹没信号）。

## 拒绝的方案

| 方案 | 结论 | 依据 |
|---|---|---|
| LLM consolidation（尾部交给 LLM 摘要合并） | 否决 | 会话 3–9 三档 +0.35 / +0.35 / +0.22，点估计最高但与规则方案差距不显著；每题多 340–980 token 调用，作答时长多 10–27% |
| Top-50 电报式 | 否决 | 会话 3–9 −0.61 [−1.47, +0.26]，不比删条好；校准集 +0.78 未复现 |
| 电报式增强版（低信息过滤 + 同日合并） | 否决 | 校准三档准确率都低于电报式 |
| LLMLingua-2 本地小模型压缩 | 否决 | CPU 上 0.9–1.3 秒/条；数字保留 78%、专名保留 80%（电报式 100% / 97%），LoCoMo 依赖二者 |
| 放进 Discloser 或作为 Retriever 后处理算子 | 否决 | 重排与删条违反铁律 10；打包依赖答题 prompt 格式，属于消费方 |
| 给 `RetrievalQuery` 加打包参数 | 暂不 | 改公共 API 需先有生产调用方；纯函数可在 `retrieve` 之后直接调用 |

## 验证

- **与实验实现逐字等价**：会话 0–9 全部 1,540 题，Top-10 / 20 / 50 自动策略输出的记忆块与实验脚本
  （上表数据的来源）逐字相同，三档 0 处差异；按 cl100k 降幅 22.6% / 21.2% / 20.4%。
- 34 个单测：自动策略分界、空输入与参数校验、官方 / 角色紧凑渲染、角色缩写例外、电报式保留规则、
  重复尾部丢弃、各策略 × 比例不超预算、逐条去向不重不漏、放不下时保留一条、自定义计数器、确定性、排序。
- 回放脚本：`--dry-run` 在上述召回上复现三档 token 降幅；接 GLM-5.2 冒烟 10 题，两组作答与判分正常落盘。
- 打包耗时（单线程，cl100k）：Top-10 / 20 / 50 每题 5 / 29 / 67 毫秒。

## 已知遗留

1. **验证范围**：只在 LoCoMo（英文）、GLM-5.2 作答、cl100k 计数、`budget_ratio=0.8`、K ∈ {10, 20, 50} 上验证。
   其他 K（如 30、200）由自动分界外推，准确率未测。
2. **默认字符估算的降幅不同**：不注入分词器时，按 cl100k 实际降幅为 22.4% / 26.6% / 20.5%（Top-20 压得更多），
   该口径下准确率未测。生产调用应注入答题模型的分词器。
3. **规则只针对英文**：角色缩写与虚词表是英文的；中文记忆基本不被电报式改写，效果退化为接近删条。
4. **调用方需自带日期**：`RetrievedItem` 不含事件时间，渲染依赖调用方提供 `created_at`
   （评测侧按 `unit_id` 反查 `temporal.t_event`）。缺失时显示 `unknown date`。
5. **大 K 的耗时**：删条与电报式每次试装都重新渲染计数，复杂度约 O(K²)；Top-200 每题约 0.6 秒（单线程，cl100k）。
6. **差异都在噪声内**：同一题 4 次运行结果不一致的约 6%，三档 CI 都跨 0；更换模型或数据集需重新校准分界。
