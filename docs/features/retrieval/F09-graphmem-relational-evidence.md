# F09 有界关系导航与原文证据

## 元信息

| 项 | 值 |
|---|---|
| 日期 | 2026-11-18 |
| 影响范围 | 查询解析、PipelineRetriever、DomainStore 和证据包 |
| 测试基线 | 候选额度、来源及关系复核、纯摘要查询、显式通道隔离 |

通过 [GraphMem overlay](../../../examples/graphmem_fact_records_overlay.yaml) 启用该路径。
复用原搜索接口，请求设置 `hierarchy_kind=time`、`hierarchy_role=time_span`、
`disclosure=L2`，并在 `Context.extensions.max_tokens` 提供正整数上下文预算。
配置环境需要本地 tokenizer，并启用关系读取和候选总体计数所需的存储能力。
当前证据包用于单空间搜索。

## 决策

查询分析提取待匹配实体、事件和软时间区间，最多使用一次已绑定模型调用，失败时
保留规则解析。初选复用词面和向量索引。只在已到达的节点及已验证的父子和关系
引用内下钻，按初选、摘要、来源和图读取的预算约束所有候选。默认示例的原文候选
最多为可见已索引原文的 10% 且不超过 128 条，摘要最多 25% 且不超过 32 条。
实际返回证据前还会复核完整 Scope、原文来源、关系版本和请求过滤。显式
`RetrievalQuery.channels` 同时约束初选和后续的索引探测。

返回的 `evidence_bundle` 包含按预算保留的证据文本、可追溯的编号、关系理由和实际
上下文 Token。可用 [回答示例](../../../examples/graphmem_evidence_reader.py) 将原文与
关联理由组织为带引用的证据段，使用 `fit_answer_budget` 给实际问题分析和回答保留
开支。启用 `include_original=false` 时只访问摘要角色。
## 拒绝的方案

无上限的关系扩展会将大部分记忆交给后续排序，增加读量与回答开支。
先在已验证的子树和关系端点内限定候选，再分配原文和摘要名额，可以控制两种成本。

## 验证

回归覆盖仅关键字请求、纯摘要访问以及预算内原文证据。公开接口测试覆盖实际来源追溯。
接口及预算语义见 [S04 检索层](../../specs/S04-retrieval.md)。

## 已知遗留

候选比例需要后端提供精确索引计数。实际聚合延迟取决于已索引的数据规模。
