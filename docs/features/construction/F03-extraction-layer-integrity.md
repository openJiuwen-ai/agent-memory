# F03 — 抽取与分层完整性最小修复

## 元信息

| 项 | 值 |
|---|---|
| 日期 | 2026-07-28 |
| 影响范围 | src/construction/，docs/specs/S05-construction.md |
| 测试基线 | construction 148 passed；全量 unit 519 passed / 1 skipped |

## 背景

长文本实验暴露两个直接影响回答的问题：抽取摘要可能省略原文事实；LLM 分层批量响应的
ID 重复或缺失时，L0/L1 可能写入错误的 MemoryUnit；无效 JSON 还可能被误当成模型明确
返回的空数组。本修复只处理构建层的数据完整性，不包含供应商错误码、动态分片或评测开关。

## 决策

- 只合并同一实体同一关系或同一事件，不按宽泛主题合并。
- 表格独立行使用 `structured_record`，可复用代码、配置、清单和方案使用 `artifact`。
- 派生 L2 只保存紧凑抽取陈述，通过 `source_ref`、`provenance` 和模型返回的最小
  `evidence` 回指来源，避免把同一完整 Source 复制进每个候选并污染索引；为兼容已有
  自定义 prompt，解析器仍接受空 `evidence`。
- 非法 JSON 或候选结构错误显式失败；合法 `[]` 仍表示模型确认没有可提取内容。
- 动态抽取仍隔离单个策略失败；若所有策略都失败则向上抛出最后一个错误，避免伪装为零记忆。
- 同一 source 内完全相同的抽取陈述只生成一次。
- 分层结果必须提供合法、唯一且完整的 ID。满足长度关系的条目暂存后写入；仅长度异常的
  条目单独跳过，不使同批合法条目丢失。
- 英文 system prompt 中原有的中文示例等价翻译为英文。

## 拒绝的方案

- **每条 L2 拼接完整 Source**：会使存储和索引按候选数成倍膨胀，并让不同候选高度相似。
- **任一长度异常整批回滚**：结构安全但可用性过低；单条摘要略长不应抹掉其他合法分层。
- **静默把非法 JSON 当作 `[]`**：无法区分模型判断和基础设施故障，会制造“零记忆”假象。
- **引入供应商专用回退**：不属于通用构建内核，留给调用方或独立 PR。

## 验证

覆盖非 JSON、非法候选、紧凑 L2、批内去重、结构化记录、重复/缺失分层 ID，以及单条
长度异常隔离。`tests/unit/construction` 共 148 项通过；全量 unit 共 519 项通过、
1 项按环境跳过；retrieval integration 共 34 项通过。修改文件通过 Ruff lint 与 Python
3.12 编译检查。

## 已知遗留

- DashScope 或其他供应商 HTTP 错误码特判；
- 无效 JSON 的 512 字符自动回退；
- recent originals 实验环境变量；
- source snapshot 或其它召回安全网；
- 新增分层实现或默认配置变更。
