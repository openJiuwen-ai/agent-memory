## 背景

常规集群和专家团共用同一条群体记忆链路。项目事实可供同项目的单 Agent 与 Team 互通，团队经验按稳定团队归属跨项目和会话使用，专家经验沿稳定模板身份积累。本方案接替 [F07](control/F07-collective-memory-design.md) 的 Swarm 群体落空间方案。通用空间治理和显式跨空间检索继续提供给各自的调用方。

## 决策

### 身份与成员治理

| 主体 | 身份与坐标 |
|---|---|
| 常规集群 | 以当前账号的 org、space、user 派生稳定团队键，使用 main_agent。跨项目的同一账号继续使用同一团队键。 |
| 专家团 | 以专家团和归属账号派生 Team，按包绑定 Group。稳定专家用模板身份，临时成员用 main_agent。 |
| 单 Agent | 使用现有身份和项目，参与同项目记忆及用户画像互通。未选项目时使用 default。 |

项目、团队和 Group 名册与主体到维度的反查保存在文档根下的 SQLite KV，同一更新原子维护两者。Swarm 在装配期通过专用身份登记项目和团队成员，并使用同一管理入口处理显式新增和撤权。团长和专家按普通成员登记。显式登记可以恢复成员权，自动装配不会恢复已移出的成员。销毁会话运行实例保留持久名册。成员主动移出、专家模板删除和专家团卸载按其业务范围同步成员关系。

SDK 由宿主绑定可信安全上下文，HTTP 由现有 Trusted 凭据认证宿主并绑定受信请求头。调用方的坐标只能收窄本次请求。群体读写逐次按调用者身份和成员权判断。HTTP 部署在监听前按 Swarm 所在组织登记专用主体，复用现有网关密钥。专用主体的操作范围限于成员管理，正文读写使用原有调用身份。

```python
from jiuwen_memory.api import COLLECTIVE_MANAGER_ID, Scope, register_trusted_principal

register_trusted_principal(
    server.authenticator, Scope(org=swarm_org, user=COLLECTIVE_MANAGER_ID), role="admin",
)
```

### 抽取和落点

Core 在含可信真人来源的成功回合，以及子任务验收后提交带角色的材料。已验证的 ask_user 回答可作为真人来源。卡片选项的证据保留字面答复，正文可由对应的已校验选项和问题得到。派单与执行输出按 Agent 或助手来源处理。验收以任务 ID 和验收版本在进程内去重。可按任务和版本合并执行者的成功回复。只有文件且缺少实质交付文本时跳过抽取。

群体材料通过原有 add 接口上的瞬态 system_metadata 提交，装配的 TeamLlmExtractor 使用共同的 Extractor 契约和模型调用入口。一次抽取产出正文、来源证据和建议落点，只向模型提供本次获准的落点。抽取按独立事项分条。同一来源可以产出不同落点的条目，每条保留自身的适用条件和具体细节，并单独引用足以支持它的原文。内核检查原文证据和写入资格。普通用户事实直接使用对应的真人引文，已校验的卡片选项使用确定性正文。已有授权项目时，同一次抽取还可识别近期有用的实际进展和已验收里程碑，归入该项目的 `daily_memory`。裸完成通知、临时审批和中间错误不入库。原始片段不入库。派生条目走共同写入编排及 Markdown 与 Shadow 存储。精确去重与文档落盘共用单行正文口径，并保留不同作者的贡献。

| 落点 | 归属与默认分享 |
|---|---|
| 用户画像 | 归用户，供该用户的 Agent 跨项目使用，shareable=true。 |
| 智能体专属记忆 | 归贡献专家，落点为 `agent`，分类为 `agent_memory`，默认 `shareable=true`。 |
| 项目、团队、Group | 按各自维度归属，默认 shareable=false。 |

### 检索与文档权限

项目落点和项目日记只在匹配项目中召回。没有项目归属的条目按所在维度的规则跨项目使用。同维度有效成员可召回团内条目，从其他上下文访问时按成员关系和显式分享状态裁决。退出后回收该维度的文档读改和其他成员条目访问权，退出者仍可逐条召回自己允许分享的贡献。召回与共享文档按 org、space、user 和成员权筛选贡献者，授权得到的候选 scope 交给公共召回执行。召回沿用经验与技能记忆的类型隔离规则。已识别的群体条目只有布尔 `shareable=true` 才可走分享分支。Work 和 Code 共用 Provider 的项目补查。当前查询项目须匹配 Swarm 绑定项目，且会话坐标为空。显式搜索和自动预取使用同一条群体项目查询，只补充项目落点。HTTP 仅在服务声明群体文档能力时启用补查。Team 的显式搜索向工具返回权限拒绝，自动预取按操作降级。项目日记、文档预取与正文修订见 [F09](F09-team-document-memory.md)。

## 方案取舍

F07 以独立空间表示归属，适用于通用空间边界。当前 Swarm 以贡献者 Scope 为条目归属，独立的索引维度和成员名册模型支持跨项目团队共享、个人经验及退团后保留原贡献。使用一次模型调用同时抽取和选择落点，沿用现有抽取、检索和文档落库端口。成员管理身份放在 Swarm 宿主，正文授权按成员及调用身份执行。

## 验证

复用 Team SDK/HTTP、Core Rail 生命周期及 Swarm 公共装配用例。验收覆盖真人来源、单次提炼、退出和再次加入、跨项目与跨账号隔离、公共空间接口和单 Agent 回归。确定性模型用于验证接线和落库行为。

- Memory 主回归 475 项通过。公开导入面调整后，HTTP 契约、SDK/HTTP Team 与访问层边界复验 148 项通过。
- Core Team/Coding Rail 和协调回归 151 项通过，19 项按测试条件跳过。
- Swarm SDK/HTTP、装配和 Work/Code 回归 363 项通过，排除一个基线 Connector 用例。统一公开导入面后，Team Runtime 复验 11 项通过。

## 已知遗留

- 移出成员后如果 Memory 同步失败，Swarm 记录失败日志。Memory 权限可能持续到撤权同步成功，补偿重试留待后续。
- 同一会话内切项目留待后续。Memory 项目坐标随 Team Provider 实例绑定，切项目时使用目标项目的会话。
- 子任务验收跨重启去重、旧版团队格式的数据迁移和多用户部署的存储根隔离留待后续。
