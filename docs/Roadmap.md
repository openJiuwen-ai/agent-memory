## V0.2.0（待发布）

本版本构建基础记忆能力，包含从数据接入、记忆构建、记忆检索、记忆管理能力，并对外提供记忆API。其主要包括以下特性

### 1. 统一记忆接口（Memory API）

- 形态无关的核心数据面：`add` / `search` / `list` / `get` / `update` / `delete` / `evolve`
- 支持批量写入（`batch_add`，目标解析与失败重映射）
- 完整 API 以 [Memory API 规约](specs/S02-memory-api.md#数据面委托-memoryengine) 为准

### 2. 编排与生命周期（Control）

- 支持按照配置或metadata进行pipeline创建
- 支持基于Space的多租户记忆隔离
- 支持中期记忆层与中期→长期的定时晋升演进

### 3. 接入层（Ingest）

- `TextSource` + `SimpleIngestor`：文本 → `MemoryUnit`（不落盘）
- `PassthroughNormalizer` 文本通路

### 4. 记忆构建与演进（Construction）

- 支持全文、向量及混合检索索引，并支持 L0/L1 内容层的可选分层索引
- 支持抽取多种记忆内容（情景、语义、程序、core），支持自定义抽取模式
- 支持构建记忆缓存，实现快速记忆检索
- 支持基于特定条件触发对缓存记忆的抽取及长期记忆构建
- 支持时序分层记忆构建
- 支持记忆冲突处理（新旧矛盾标记失效保留血缘、近重复记忆融合压缩）
- 支持视频多模态记忆构建（视频流水线 + 多模态抽取）
- 支持可选的实体 Schema 抽取（自定义 schema 驱动实体/关系抽取）
- 支持实体关联记忆构建（实体反向索引，全链路至检索扩展召回）
- 支持 LLM 分层抽取（一次抽取产出 L0/L1/L2 分层内容并保证层间完整性）
- 支持动态抽取与 LLM 驱动巩固决策（merge / supersede 等）
- 支持接入 DashScope LLM 与 ASR 模型服务

### 5. 记忆检索（Retrieval）

- 支持对查询进行解析及向量化
- 支持扁平及树状Filter过滤
- 支持按配置启用基于关键词、向量、图的召回
- 支持分层召回，并支持 RRF、加权 RRF、Score Max 等融合方式
- 支持渐进式披露召回
- 支持多模态记忆检索
- 支持基于实体反向索引的扩展召回

### 6. 记忆存储（Storage）

- 支持可配置的 KV / Vector / Fulltext / Graph / Fusion / FS 存储能力
- 已提供可选生产后端适配器：SQLite KV、Redis KV、PostgreSQL（KV / PGVector）、Milvus、Elasticsearch、nano_graphrag、Milvus Graph Fusion、本地 FS；使用时需部署相应依赖并完成连接配置
- 外部后端连接支持 SSL/TLS 加密配置（Redis / ES / PG / Milvus）
- 支持配置路由存储（按 `active` 名切换整套存储/模型实例）

### 7. 多形态接入面（Bootstrap）

- 支持 Python Core API 进程内嵌入
- 支持 HTTP Server 接入

### 8. 群体记忆（Agent Team）

- 支持群体记忆构建与跨空间召回（collective memory / agent team 模式）

### 9. Agent 插件

- JiwenSwarm `MemoryProvider` 适配（进程内 / HTTP）

### 10. 评测框架

- 支持LoCoMo / LongMemEval 进行评测

## V0.2.1 （规划中）

- 支持审计事件与审计日志（治理事件持久化与查询）
- 支持分布式锁公共组件（Redis / 内存实现）

- 支持对接OpenClaw
- 支持对接ClaudeCode

## 规划原则

1. **V0.2.0 为能力基线**：后续版本只增能力或硬化，不轻易破坏 Core API 语义；破坏性变更需升 minor 并写迁移说明。
2. **features 归档纪律不变**：影响公开接口或跨模块取舍的特性，仍按「代码 → 测试 → docs/features」三连提交。
3. **与 design 的关系**：`docs/design/` 为长期愿景；本 Roadmap 是可执行切片。design 中开放问题（architecture §17）在对应版本立项时再定案。
